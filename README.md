# RPG Asset Studio

Графическая утилита и CLI для извлечения ассетов из игр на **RPG Maker MV / MZ / VX Ace**,
**WOLF RPG**, **Pixel Game Maker MV** и **Unity**: поиск ключа шифрования, расшифровка картинок, аудио и видео,
распаковка архивов, выгрузка текста для перевода.

```bash
python -m pip install -r requirements_unity.txt
python rpg_maker_gui.py
```

Для RPG Maker и WOLF хватает чистого Python — PyQt6 нужен только окну, а UnityPy и Pillow
только Unity-режиму.

## Сохранять структуру папок

Главный переключатель в окне: **«Сохранять структуру папок»**.

| Режим | Что получается | Когда нужен |
| --- | --- | --- |
| **Включён** (по умолчанию) | `images/img/pictures/Actor1.png` — раскладка как в игре | нужно понимать, откуда файл, или вернуть его обратно в игру |
| **Выключен** | `images/Actor1.png` — всё в одной папке | нужны «просто картинки», без лазанья по папкам |

В плоском режиме:

- **Совпадающие имена не перетирают друг друга.** Второй `Actor1.png` получает имя папки в
  качестве префикса: `characters_Actor1.png`. Если и так занято — берётся следующий уровень
  вложенности, и лишь в самом конце добавляется номер.
- **Дубликаты пропускаются.** Одинаковый по содержимому файл, лежащий в игре в нескольких
  местах, копируется один раз; в лог попадает строка вида
  `Flat output: skipped 4 duplicate image(s) with identical content.`
- **Имя для одного и того же исходного пути не меняется** между запусками, поэтому повторный
  запуск в ту же папку не создаёт вторую копию под другим именем.

Разбивка по типам (`images/`, `text/`, `audio/`, `fonts/`) в Unity-выводе сохраняется в обоих
режимах — плоским становится только то, что внутри. Для RPG Maker MV/MZ расшифрованные ассеты
лежат прямо в `extracted/` и отдельной копии в `images/` не создаётся.

Особенность WOLF RPG: сырую распаковку делает внешний `UberWolfCli`, поэтому папка
`extracted/` остаётся в своей раскладке, а плоский режим применяется к `images/`. Программа
пишет об этом предупреждение в лог.

Выбранный режим записывается в `manifest.json` / `unity_manifest.json` полем
`folder_structure`: `preserve` или `flatten`.

### В командной строке

```bash
# структура сохраняется (по умолчанию)
python rpg_maker_tool.py extract "C:\Games\MyGame" -o out

# всё в одну папку
python rpg_maker_tool.py extract "C:\Games\MyGame" -o out --flat

# только расшифровка картинок, плоским списком
python rpg_maker_tool.py decrypt "C:\Games\MyGame" -o out --types image --flat
```

`--flat` у `decrypt` требует `-o/--out`: расшифровка «на месте» оставляет файлы там, где они
лежат, складывать их некуда.

## Три режима и кнопки

Режим выбирается в карточке **«Что делаем»** и определяет, что именно получится. Главная
кнопка внизу подписана именем режима, под переключателем всегда написано «Что получится».

| Режим | Кнопка | Результат |
| --- | --- | --- |
| **Только файлы** | «Расшифровать файлы» | Выбранные типы, расшифрованные, прямо в папке вывода. Ни текста, ни отчётов |
| **Полное извлечение** | «Извлечь всё» | `extracted/` — выбранные типы (расшифрованные + незашифрованные), `translation/translation.jsonl` — текст, `manifest.json` — отчёт |
| **Проект для редактора** | «Собрать проект» | Копия игры в раскладке редактора RPG Maker |

Остальные кнопки:

- **Проверить игру** (в карточке «Игра») — движок, ключ шифрования, сколько файлов зашифровано
  и сколько лежит незашифрованными. Ничего не записывает.
- **Предпросмотр** — показывает, что будет сделано **в текущем режиме**: какие файлы куда
  попадут, сколько расшифруется, что появится помимо ассетов. Ничего не записывает.
- **Отмена** (`Esc`), **Открыть результат**, **Копировать/Очистить** журнал, переключатель темы.

Галочки «Картинки / Аудио / Видео / Текст / Шрифты» действуют в режимах «Только файлы» и
«Полное извлечение»; «Текст» и «Шрифты» — только в полном извлечении. В режиме проекта
копируется вся игра, поэтому фильтры и раскладка папок отключаются.

Для Unity доступно только «Полное извлечение» — два других режима отключаются, а если был
выбран один из них, программа сама переключится.

## Режим «Проект для редактора»

Собирает из выпущенной игры папку, которую сразу открывает редактор RPG Maker:

- `www/` раскрывается в корень проекта — получается привычная раскладка
  `audio/ data/ fonts/ icon/ img/ js/ movies/ + Game.rpgproject + index.html + package.json`;
- все зашифрованные ассеты расшифровываются на месте: `.rpgmvp → .png`, `.rpgmvo → .ogg`,
  `.rpgmvm → .m4a`, `.png_/.ogg_/.m4a_` — тоже;
- в `data/System.json` снимаются флаги `hasEncryptedImages` / `hasEncryptedAudio` и удаляется
  `encryptionKey`, иначе игра продолжила бы искать зашифрованные файлы;
- `package.json` перенастраивается с `www/index.html` на `index.html`;
- если в сборке нет файла проекта, создаётся `Game.rpgproject` (MV) или `Game.rmmzproject` (MZ);
- движок игры (`Game.exe`, `*.dll`, `locales/`) не копируется — включается галочкой
  «Копировать движок игры (exe, dll)» в «Дополнительно»;
- рядом кладётся `project_manifest.json` со статистикой.

Имя папки подставляется автоматически: `Marie's Adventure_project`. Путь выбирается там же,
где и для обычного извлечения.

Режим работает с RPG Maker MV и MZ. Повторный запуск в ту же папку по умолчанию не трогает уже
записанные файлы — для полной пересборки включите «Перезаписывать существующие файлы».

```bash
# проект рядом с папкой по умолчанию: <вывод>/Marie's Adventure_project
python rpg_maker_tool.py project "D:\H14\Marie's Adventure"

# свой путь и копия движка
python rpg_maker_tool.py project "D:\H14\Marie's Adventure" -o "D:\Projects\Marie" --include-runtime
```

## Pixel Game Maker MV

Отдельный движок (Cocos2d-based), не RPG Maker: всё лежит в `Resources/`, игра описана одним
`Resources/data/project.json` на сотни мегабайт, метаданные защиты — в `Resources/data/info.json`.

Что уже работает:

- **определение движка** с версией проекта и плеера (`project 1.0.6, player 1.0.6.3`),
  уверенность ≥ 0.9; движок есть в списке GUI и в `--engine pixel-game-maker-mv`;
- **перепись ресурсов по содержимому, а не по расширению.** Защищённый файл всё равно
  называется `.png` — «Проверить игру» показывает раздельно защищённые, открытые и нечитаемые,
  плюс какие заголовки защиты встретились (`enc×2237`);
- **извлечение открытых ресурсов** — картинки, аудио, шрифты; защищённые не копируются
  «как есть», чтобы в результате не оказалось файлов с расширением `.png`, которые не
  открываются;
- **текст локалей** из `textList`: `project.json` не грузится в память целиком — нужное
  значение находится по файлу и разбирается отдельно, поэтому 300 МБ не проблема. Экспорт
  идёт в `translation/translation.jsonl` с идентификатором записи, контекстом, языком и
  шрифтом; теги вида `\V[1]` сохраняются как есть;
- **отчёт** `manifest.json`: версии, защищённые и открытые по типам, заголовки защиты, статус
  ключа (без самого значения), список локалей с количеством записей, длительность.

Чего пока нет: **расшифровки защищённых ресурсов** и **обратного импорта перевода**. Формат
защиты PGMMV не документирован и не проверен на реальных файлах, поэтому программа не
притворяется, что умеет это: защищённые файлы считаются и остаются на месте, а в лог и
`manifest.json` пишется, что формат не поддержан. Режимы «Только файлы» и «Проект для
редактора» для PGMMV отключаются — доступно «Полное извлечение».

## Имя папки вывода

Название берётся из самой игры, а не из выбранной папки. Можно указать хоть
`D:\H14\Marie's Adventure\www\img` — программа поднимется до корня игры, прочитает
`gameTitle` из `System.json` и предложит `Marie's Adventure` (или
`Marie's Adventure_project` в режиме проекта). Если названия в игре нет, берётся имя папки
игры, а не служебной `img`, `www`, `audio` и т. п.

Оттуда же ищется и ключ шифрования: при выборе подпапки поиск ключа автоматически
продолжается в корне игры, где лежат `System.json` и плагины.

## Интерфейс

- Тёмная и светлая темы, переключаются кнопкой в шапке; выбор запоминается.
- Экран собран по шагам: игра → что делаем → куда сохранить → структура папок → что
  извлекать, редкие настройки убраны в сворачиваемую карточку «Дополнительно».
- Путь результата и пример раскладки показываются до запуска.
- Папку или файл можно перетащить прямо в окно.
- Журнал подсвечивает ошибки, предупреждения и итоги; его можно скопировать одной кнопкой.
- Прогресс показывает обработано/всего, процент и время работы.
- Кнопка «Открыть результат» открывает папку с извлечённым в файловом менеджере.
- Поля, галочки и размер окна восстанавливаются при следующем запуске.
- Горячие клавиши: `Ctrl+O` — выбрать папку, `Ctrl+Enter` — запустить текущий режим,
  `Esc` — отмена.

| --- | --- |
